## 3. 발견 사항

### F1 — 접힌 상세 행 사이 빈 공간
- 관점: 정확성.
- 근거: 펼친 상태의 전체 y좌표를 그대로 둔 행 때문에 요약 아래 빈 공간이 생겼다.
- 처리: 행 자체를 연속 배치하고 자식 레이아웃과 겹침 검사를 유지했다.

### F2 — 캐시 검증과 준비 오류의 해석
- 관점: 계약 정합성.
- 근거: 실제 verify 값은 pass/fail 외에 cached-pass, cached-fail, none, error도 사용한다.
- 처리: 결과별 표시와 설명을 구분하고 전체 도구 성공률로 합산하지 않았다.

### F3 — 미수집 캐시 필드의 0 표시
- 관점: 정확성.
- 근거: 기존 Codex cache_write_1h는 실제 관측 없이 0으로 채워진다.
- 처리: 기존 원천 진단의 해당 시리즈는 숨기고 원천 쿼리 회귀 검사는 보존했다.

## 5. 단위 간 정합성

- 수집·인증·보관 정책·환경변수·서비스 경계 변경 없음. Grafana 표시·조회 설정과 검증 코드만 변경했다.
- hooks 차단·검증 동작, 네이티브/기존 누적 원천은 보존한다. 기존 혼합 비용은 접힌 진단에 남기며 공통 사용량과 합산하지 않는다.
- 새 진단은 사람·저장소 필터를 적용하며, 기존 원천 진단 행은 필터 미적용임을 표시한다.
- 생존 신호는 에이전트 실행 상태가 아니다. 기록 없음과 0·미지원·미수집·조회 오류를 구분한다.
- 토큰 중심 사용량·작업 근거 스크린샷은 별도 작업의 적용 예시임을 README에 명시했다.
- 목데이터는 로컬의 가상 저장소·가상 팀원·가상 작업만 사용했다. 이미지에 운영 사용자 기록이 없음을 확인했다.
