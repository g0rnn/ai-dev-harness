# 작업·PR별 에이전트 기록

한 채팅에서 여러 worktree를 수정해도 Codex 세션의 시작 폴더는 그대로다. 기존 브랜치 집계는
실제 수정한 작업이 아니라 그 시작 폴더의 브랜치로 기록을 모을 수 있다. PR 본문에는 명시적으로
연결한 작업·PR 범위의 요약을 사용한다. 브랜치 이름만으로 작업을 추정하지 않는다.

## 시작과 전환

대상 저장소에 새 키트를 적용한 뒤, 작업을 시작할 때 실행한다. Codex에서는 `CODEX_THREAD_ID`가
있으면 `--session`을 생략할 수 있다. 다른 도구는 세션 ID를 명시한다.

```sh
python .harness/summary.py bind --task TEAM-140 --session SESSION-ID
```

같은 세션에서 다른 작업을 시작하면 새 작업으로 연결한다. 이전 구간의 종료와 새 구간의 시작을
한 번의 원자적 저장으로 남긴다. 같은 작업으로 재연결해도 시작 경계가 바뀌지 않는다.

```sh
python .harness/summary.py bind --task TEAM-143 --session SESSION-ID
python .harness/summary.py unbind --session SESSION-ID
```

키트 경로에서는 `python bin/harness.py agent bind <대상 저장소> --task ... --session ...` 형태로 실행한다.
연결은 기본적으로 명령 실행 시각부터다. 과거 경계를 확정할 증거가 있을 때만 `--since`에 시간대가
포함된 시각을 명시한다. 기존 시작 경계·이미 닫힌 구간을 조용히 덮어쓰지 않으며 미래 경계도 받지 않는다.

## PR이 생긴 뒤 연결

```sh
python .harness/summary.py link --task TEAM-143 --pr 143
python .harness/summary.py agent --pr 143
```

PR 연결은 기존 작업의 시작 시각을 바꾸지 않는다. 한 작업은 이 저장소의 한 PR/MR 번호에 연결한다.
여러 PR로 나눌 작업은 서로 다른 작업 ID를 사용한다. 이미 연결한 PR을 다른 번호로 덮어쓰지 않는다.

```sh
python .harness/summary.py agent --task TEAM-143
python .harness/summary.py sessions --pr 143
python bin/harness.py agent summary <대상 저장소> --pr 143
```

`agent`는 PR 본문용이고 `sessions`는 사람이 관측된 일부 값까지 확인할 때 쓴다. 연결 정보가 있는
저장소에서 범위 없는 기본 요약은 작업 또는 PR 선택을 요구한다. 기존 브랜치 참고 집계가 필요하면
`--branch <이름>`을 명시한다. 이 참고 값을 PR 단독 사용량으로 옮기지 않는다.

## 정확히 나눌 수 없는 기록

- 연결 전 기록을 새 PR에 소급 귀속하지 않는다. 연결이 없는 범위는 브랜치로 대체하지 않는다.
- 누적 사용량은 전체 관측 순서에서 차이를 계산한 뒤 범위를 선택한다. 누적 100에서 300으로 늘어난
  두 관측 사이에 작업이 바뀌었다면 증가분 200을 어느 작업에도 임의로 나눠 넣지 않는다.
- 이처럼 경계를 가로지른 토큰, 겹친 연결, 미관측 기록이 있으면 PR용 `agent` 출력은 **기록 없음·완전한 귀속 미확정**이다.
  확인된 일부 값은 `sessions --task/--pr`로 볼 수 있지만 완전한 PR 비용으로 내보내지 않는다.
- 응답 수는 완료 사건의 구간 기준이고 작업 시간은 같은 연결 구간 안에서 관측한 사건 사이 시간이다.
  실제 인력 작업 시간이나 생산성으로 해석하지 않는다.
- 자식 세션은 자체 연결을 우선하고 없으면 부모 연결을 따른다. 자식 토큰을 포함해도 부모 응답 수를 중복 증가시키지 않는다.
- PR 범위에 커밋을 정확히 연결하는 별도 근거가 없으므로 작업/PR 요약에는 기존의 '기록 없는 커밋' 비율을 출력하지 않는다.

## 저장 위치와 #141 호환

새 연결은 저장소 공통 Git 디렉터리의 `harness/attribution.json`에 저장한다. 같은 저장소의 worktree가
한 연결 이력을 공유하며 파일 잠금과 원자적 교체로 보호한다. 로컬 상태이며 커밋·원격 전송하지 않는다.
세션 ID·작업 ID·PR 번호·시각만 저장하고 프롬프트·응답·코드·인증정보는 저장하지 않는다.

#141의 각 worktree `harness/agentops/bindings.json`이 있으면 이력 구간을 읽기 전용으로 사용한다.
그 파일을 새 형식으로 다시 쓰거나 기존 수집기를 실행하지 않는다. 동일한 연결 복사본은 한 번만 사용하고,
작업 연결이 충돌하면 임의의 우선순위로 해결하지 않는다. 손상된 파일은 집계를 중단하며 0으로 처리하지 않는다.

자동 watcher·OS 예약 작업·알림 hook·서버 전송·기존 PR 본문 재배분은 이 기능에 포함하지 않는다.
