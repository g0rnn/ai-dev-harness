# 개발 계획

기준일 2026-09-29(M5 추가 2026-10-20). 이 문서는 키트 완성(2단계)까지의 목표, 마일스톤, 작업 목록과 범위 밖을 정의한다.
마일스톤이 끝날 때마다 완료 기준 충족 여부와 측정값을 이 문서에 추기한다.

## 1. 목표

한 문장: **새 저장소를 만든 날부터 AI 산출물이 표준을 벗어나면 기계가 막고, 그 효과를 숫자로 보이는 키트.**

| 목표 | 측정값 | 기준 |
| --- | --- | --- |
| 적용 비용 | 빈 저장소에 키트를 붙여 첫 MR을 엄격 단계 절차까지 통과시키는 시간 | 반나절 이내 |
| 방어 효과 | 병합 후 뒤늦게 발견된 누락 수, 보안 검사가 잡은 건수 | 이전 프로젝트 대비 감소, 검사 4종 모두 실제 검출 사례 1건 이상 |
| 팀 수용 | 절차를 건너뛴 MR 비율, 팀원이 hooks를 끈 횟수 | 0에 가깝게 |
| 에이전트 운영 | MR당 에이전트 세션 수·토큰·추정 비용, 도구별 결과 비교, hooks 미등록 세션 수 (M5) | 모든 MR에서 기록되고, 작업 중에 실시간으로 보인다 |

측정 항목은 1주차에 자리를 잡는다. 플랫폼 API(병합 MR·이슈·CI job)에서 다음 다섯을 뽑는다(M4-1 `harness metrics collect`, `core/metrics/README.md`).

1. 병합 후 발견된 누락 수 (`escaped-defect` 라벨 이슈·MR의 원인 MR 병합 주. 리뷰 템플릿 6장 측정 칸은 보조)
2. 엄격 단계 MR 비율 (MR 본문 `## 판정`과 변경 파일 재판정 중 높은 쪽)
3. CI 실패 원인 분류 (테스트 실패 · 포맷 · 인프라 · 타임아웃 · 보안 · 미분류)
4. 판정 스크립트와 사람 판정의 불일치 수 (본문 판정 ≠ 재판정)
5. hooks 개입 수와 보고 MR 수 (MR 본문 `## hooks 기록`. 미보고 MR 수는 hooks를 끈 횟수의 대리 지표, M4-7)

M5에서 다음 셋을 더한다. 출처는 지표 5와 같이 각자의 worktree 기록을 MR 본문에 옮긴 절이고, 주 단위로 집계한다.

6. MR당 에이전트 비용 (MR 본문 `## 에이전트 기록`의 세션 수·작업 시간·토큰·추정 비용. 중앙값과 합계, M5-3)
7. 도구별 결과 (MR을 작업한 도구(Claude Code·Codex·사람)별 MR 수와 그 MR들의 CI 실패율·병합 후 누락·판정 불일치, M5-3)
8. 리뷰 효과 (MR 본문 `## 리뷰 결과`의 채택·기각·후속 수, A·B 독립 중복 발견률. 엄격 MR당 채택 결함 수, M5-4)

## 2. 단계

| 단계 | 기간 | 산출물 | 완료 기준 |
| --- | --- | --- | --- |
| 1. 착수판 | 2주 | 템플릿 묶음, hooks, 보안 검사 4종 CI | 빈 저장소에 붙여 첫 MR이 엄격 단계 절차까지 통과 |
| 2. 키트 완성 | 다음 프로젝트 기간 중 6~8주 | 1단계 + 판정·리뷰 자동화, Scaffold, 측정 수집기, 가이드와 리허설 기록 | 실제 프로젝트 한 개에서 전 기간 사용, 전후 측정값 확보 |
| 3. 플랫폼 | 별도 프로젝트 | 포털, 승인·이력, 운영 관리, 거버넌스 RAG | 이 계획의 범위 밖. 2단계 결과가 좋을 때 별도 계획으로 올린다 |

### M5. AgentOps (M4 이후, 다음 프로젝트 기간)

완료 기준: 모든 MR 본문에 에이전트 기록(세션·토큰·추정 비용·도구)이 남고 주간 리포트가 지표 6~8을 보이며,
작업 중에는 로컬 대시보드로 진행 중 세션과 hooks 개입을 실시간으로 본다. hooks가 없는 도구로 작업한 MR도 CI가 같은 보호 경로를 검사한다.

지금 지표는 병합 단위 결과(무엇이 새어 나갔나)만 본다. M5는 세션 단위 사실(에이전트가 무엇을 했고 얼마가 들었나)을 더한다.
기록은 M4-7과 같은 경로(각자의 worktree 기록 → MR 본문 절 → 플랫폼 API 수집)를 쓰고 표준 라이브러리만 쓴다. 팀 공용 실시간

## 5. 범위 밖

포털 UI, SSO, 운영 관제(알림 당번·SLO·수집기 호스팅과 백업), 거버넌스 RAG, 비활성 서비스 Lifecycle. 회사 인프라 없이 만들면
흉내가 되므로 2단계 결과를 본 뒤 3단계 계획에서 다룬다.

에이전트 관측은 M5에서 범위를 나눈다. 로컬 실시간 대시보드(M5-7)는 인프라 없이 키트 안에서 동작하므로 범위 안이다.
팀 공용 대시보드(M5-8)는 수집기·저장소가 필요하므로 켜는 팀이 운영하는 선택 조각으로만 제공하고, 그 운영은 범위 밖이다.

## 6. 원칙

- **일반화를 미리 하지 않는다.** 두 번째 적용 전에 추상화하지 않는다. 다음 프로젝트 스택 하나만 겨냥한다.
- **기본은 가볍게, 엄격은 트리거로.** 경량·표준 경로는 hooks와 CI만 조용히 돈다. 플랜 승인과 분리 리뷰는 판정이 엄격일 때만 켠다.
- **측정을 첫 기능으로.** 숫자로 못 보이면 취미다.
- **키트가 키트를 쓴다.** 만들어진 즉시 이 저장소에 적용하고, 불편은 이슈로 남긴다.
