# {{area_dir}} AGENTS.md

루트 `AGENTS.md`를 전제로 `{{area_dir}}/`에서 작업하는 AI 코딩 도구의 판정, 절차와 기록을 정한다.
루트에 있는 규칙(기존 변경 보호, 테스트 약화 금지, worktree 분리, 완료 보고)은 반복하지 않는다.

규칙 끝의 표시는 그 규칙을 누가 지키게 하는지다. `[hook]` 로컬 hooks, `[ci]` CI, `[사람]` 작업자와
리뷰어. `[hook]`·`[ci]` 규칙도 해당 장치가 설치되기 전까지는 사람이 확인한다.

## 1. 기준 문서

{{area_docs}}

계약과 다르게 구현해야 하면 임의로 진행하지 않고, 합의한 뒤 기준 문서를 먼저 고친다.

## 2. 검증

{{area_verify}}

완료 검증은 파일을 수정하지 않는 명령으로 하고, 작업 범위 밖의 파일을 고치지 않는다.

## 3. 판정

변경이 닿는 범위로 세 단계 중 하나를 고른다. 섞이거나 애매하면 가장 높은 단계를 따른다.

| 단계 | 조건 | 적용 |
| --- | --- | --- |
| 경량 (`lite`) | 문서·주석, 또는 생산 동작과 계약을 바꾸지 않는 테스트만 변경 | 2장 검증. 플랜·리뷰 파일을 만들지 않는다 |
| 표준 (`standard`) | 트리거에 해당하지 않음 | 4장 산출물을 한 세션에서 만든다 |
| 엄격 (`strict`) | 트리거 하나 이상 | 4장 산출물에 플랜 승인과 분리 리뷰를 더한다 |

트리거. diff나 플랜에 하나라도 있으면 해당한다. 테스트 코드와 테스트 리소스만 바꾼 변경은 트리거로 보지 않는다.

{{area_triggers}}

- 판정과 근거는 표준·엄격이면 플랜 첫 줄에, 경량이면 시작 보고와 {{pr_noun}} 본문에 적는다. [ci]

## 4. 절차

표준·엄격 단계는 플랜, 구현, 리뷰 산출물을 남긴다. 양식은 `docs/templates/plan.md`와 `review.md`다.

- **플랜** `plans/<{{issue_key}}>.md`: 설계, 미확정 항목, 기준선(시작 커밋과 기존 미커밋 변경), 판정과 트리거, 조건부 관점, 인수 테스트 목록을 적는다. [hook]
- 인수 테스트는 동작마다 이름·전제·입력·기대 결과를 적고, 테스트로 확인할 수 없는 변경은 대체 검증과 통과 조건을 둔다. [hook]
- 플랜 완료 기준: 모든 동작에 테스트나 대체 검증이 대응하고, 계약·공용 파일 영향이 합의돼 있다. [사람]
- **구현** 완료 기준: 2장 검증이 통과한다. [ci]
- 플랜의 인수 테스트가 모두 코드에 있다. [hook]
- 플랜 대비 테스트의 추가·삭제·기대값 변경과 플랜 이탈은 사람 확인 후 플랜에 기록한다. [사람]
- **리뷰** `plans/<{{issue_key}}>-review.md`: 변경 단위마다 diff와 그 단위가 참조하는 계약 절만 읽고 아래 관점(원본 `review-perspectives.md`, CI 리뷰와 공통)을 한 번에 적용한다. [사람]
{{review_perspectives}}
- 이 영역에서 특히 볼 관점(공통 관점에 덧붙임): {{area_review_focus}}. [사람]
- 플랜과 리뷰의 측정 칸을 비워 두지 않는다. [hook]
- A와 B는 `-review-A.md`와 `-review-B.md`에 따로 쓰고 서로의 파일을 읽지 않는다. 반영 전에 AI가 합집합 대조표를 `-review.md`에 리뷰 템플릿 7장 표 형식(결함 한 줄 요지·심각도·발견 `A F1, B F3`)으로 만들어 세션별 번호를 유지한 채 채택·기각·후속을 표시하고, 사람은 갈래가 있는 항목만 판단한다. [사람]
- 엄격 단계의 **플랜 승인**: 사람이 승인이나 수정 지시를 플랜 결정 기록에 적은 뒤 구현을 시작한다. [hook]
- 엄격 단계의 **분리 리뷰**: 구현과 다른 세션에서 플랜, diff와 기준 문서만 보고 리뷰한다. [사람]

## 5. 기록

- 플랜과 리뷰 파일은 저장소 루트 `plans/`에 두고 커밋하지 않는다. `.gitignore`에 `/plans/`가 있어야 한다. [ci]
- 최종 리뷰 파일(표준은 리뷰 파일, 엄격은 합집합 대조표)만 `python .harness/summary.py review <파일> --save`로 `docs/reviews/<{{issue_key}}>.md`에 저장해 {{pr_noun}}과 함께 커밋하고, 커밋 전에 Secret·개인정보를 점검한다. worktree에서 만든 플랜과 리뷰 원본은 worktree를 정리하기 전에 기본 체크아웃의 `plans/`로 옮긴다. [사람]
- {{pr_noun}} 본문에 판정, 플랜 요약, 플랜 대비 변경점, 리뷰 결과, 인수 테스트 목록과 측정 칸을 옮긴다. [ci]
- 계약·스키마·규칙 변경은 플랜이나 {{pr_noun}}에만 두지 않고 기준 문서에 반영한다. 프로젝트 수준 결정은 `docs/adr/`로 올린다. [사람]
- 검토 후보: 엄격 {{pr_noun}} 5건 연속으로 사후 누락이 0이면 분리 리뷰 완화를(커밋된 리뷰 파일의 발견 세션별 수를 함께 본다), 표준 {{pr_noun}}에서 사후 누락이 나오면 트리거 확대를 검토한다. 사후 누락은 병합 후 리뷰 측정 칸에 기입한다. [사람]
